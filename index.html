Not every mistake can be undone

An agent that is eighty percent sure about renaming a file and eighty percent sure about authorising a payment gets the same verdict from a confidence gate. Guardrail predicts what the call would cost to undo, and stops for a human only when the expected damage is worth the interruption.

Confidence and consequence are orthogonal

Every deployed safeguard we know of gates on one number: how sure the model is. That number partitions the action space vertically. Safety needs a horizontal cut. Drag the gate and watch what a confidence threshold can and cannot separate.

Raise the threshold to protect the transfer and you buy approval requests for thousands of harmless file operations. Lower it to keep the agent useful and the transfer goes through unguarded. No vertical line separates the two populations.

Every tool call passes through three components

Guardrail sits between the agent and its tools, at the function-call boundary that all mainstream frameworks share and at the Model Context Protocol transport. Nothing about the agent changes.

db.dropTable("users")
01

Intercept

The proposed call is held before execution. The tool name, arguments, destructive flags, wildcard scope and target sensitivity are read off the call itself.

02

Undo-cost regressor

An asymmetric quantile loss makes under-prediction expensive. Split conformal calibration turns the estimate into a distribution-free interval, and the policy consumes the upper bound.

03

Silent-irreversibility detector

A contextual head reads trajectory history. A compositional head tracks which recovery affordances remain, so a call that removes the last one is amplified even when it looks cheap.

04

Escalation policy

Thresholds are learned per action class against realised cost, under a bounded interruption rate. The verdict is execute, or hand it to a person.

Perr × U(a, s, h) > Cint

Escalate when the expected damage of proceeding exceeds the certain cost of pausing. The threshold is a function of the action, not a constant.

Four calls, one rule

Undo cost decomposes into recovery latency, monetary exposure and social exposure. Only the first two can be measured by executing a rollback in the sandbox. The third is assigned from the externality axis and is reported as an assumption, not a measurement.

Two reversible actions, one irreversible state

Take the same two calls in three arrangements. On their own, each one leaves a way back. Run them in sequence and there is no way back at all, even though neither call changed.

Each call is scored cheap on its own, and correctly so. Guardrail carries which recovery paths are still standing, so the second call is priced against a world in which the first one already happened. A rule list, scoring every call in isolation, passes all three of these.
